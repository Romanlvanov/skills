# Git-хостинги

> Обзор сделан в 2026-10, актуальность не гарантируется. Используй его, чтобы сориентироваться, затем сам исследуй актуальные варианты: продукты, цены, лимиты и беты меняются быстро.

## Типы

### Платформы «всё в одном»

Git-хостинг в комплекте с трекером тикетов, CI-системой, которая служит оркестратором, и хостируемыми раннерами, и всё это с одним потоком событий и одной моделью прав. Один продукт заполняет git-хостинг, трекер тикетов, оркестратор и раннер, а страницы его CI-прогонов часто покрывают и платформу наблюдаемости. Каждое событие PR, ревью, метки и проверки является и вебхуком, и встроенным триггером, поэтому у этого типа самый богатый каталог триггеров.

**Выбирай его, когда** фабрика начинает с малого, код уже живёт там или пользователь хочет один счёт и один логин. Это схема «All on GitHub» в [SKILL.md](SKILL.md). Вендоры также поставляют собственных агентов, которые либо конкурируют с прогонами пользователя, либо встраиваются как один из них.

- [GitHub](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api): вариант по умолчанию; Issues, Actions, Apps и самая большая экосистема интеграций.
- [GitLab](https://about.gitlab.com/pricing/): задачи, merge requests, CI/CD и раннеры в одном продукте, SaaS или self-managed.

### Git-хостинги в составе пакета

Git-хостинг, который продаётся как один модуль более широкого пакета, где трекер тикетов является соседним продуктом (Jira, Azure Boards), связанным ссылками и вебхуками. События трекера приходят по второму потоку, поэтому оркестратор объединяет два источника событий.

**Выбирай его, когда** организация уже использует этот пакет, а её люди живут в Jira или Azure Boards. Фабрика наследует этот трекер как свой человеческий интерфейс.

- [Bitbucket Cloud](https://support.atlassian.com/bitbucket-cloud/docs/api-request-limits/): git-хостинг Atlassian в паре с Jira и Bitbucket Pipelines.
- [Azure DevOps (Azure Repos)](https://learn.microsoft.com/en-us/azure/devops/integrate/concepts/rate-limits): Repos, Boards, Pipelines и идентичности Entra в одной организации, так что он заполняет все четыре слота.
- [AWS CodeCommit](https://aws.amazon.com/blogs/devops/aws-codecommit-returns-to-general-availability/): голый git-хостинг с идентичностями IAM; используй его в паре с внешним трекером и CI.

### Self-hosted git-хостинги

Git-хостинг, который пользователь запускает на своей инфраструктуре, часто рядом с оркестратором и раннерами в той же сети. Rate limits задаёт оператор, поэтому потолок определяет железо. Обновления, бэкапы и аптайм каждого заполняемого им слота лежат на пользователе.

**Выбирай его, когда** код должен оставаться on-premises или в изолированной сети, пользователь хочет нулевую стоимость за место или бюджет SaaS API душит загруженную фабрику. Forgejo и Gitea подходят маленьким командам и включают задачи плюс CI, совместимый с GitHub Actions; GitLab self-managed и GitHub Enterprise Server подходят организациям и сохраняют свои Apps и сервисные аккаунты.

- [Forgejo](https://forgejo.org/2026-10-release-v17-0/): под управлением сообщества, лёгкий, с Forgejo Actions.
- [Gitea](https://about.gitea.com/): лёгкий, с Gitea Actions; продаётся также как управляемый сервис.
- [GitLab self-managed](https://about.gitlab.com/install/) и [GitHub Enterprise Server](https://docs.github.com/en/enterprise-server@latest): полные платформы на собственной инфраструктуре пользователя.

### Git-хостинги с упором на ревью и децентрализованные

Git-хостинги, чья модель ревью отходит от схемы «ветка и PR»: патчсеты на каждый коммит с голосованием метками или репозитории, федеративно распределённые по узлам, которые держат пользователи. Большая часть инструментов фабрики предполагает PR, так что рассчитывай написать больше клея. В Gerrit прогон автоматической проверки голосует `Verified` с бот-аккаунта, а человек голосует `Code-Review`.

**Выбирай его, когда** команда пользователя уже ревьюит так или ценит федерацию выше экосистемы.

- [Gerrit](https://www.gerritcodereview.com/): ревью патчсетов с голосованием метками; модель Android и Chromium.
- [Tangled](https://blog.tangled.org/ci/): git-хостинг на AT Protocol со стековыми PR и собственным CI-раннером.

### Git-хостинги, изначально рассчитанные на агентов

Новые git-хостинги, построенные вокруг агентов как основных авторов: высокая пропускная способность по коммитам, чтение на стороне сервера вместо клонов и атрибуция по агентам. Весь тип ещё ранний (на 2026-10), поэтому шлюзы и rate limits могут быть не опубликованы: спроси вендора.

**Выбирай его, когда** фабрика гоняет много параллельных прогонов по одному большому репозиторию, и время клонирования или лимиты API становятся главным ограничением. Опробуй его на зеркале одного репозитория, оставив GitHub запасным вариантом.

- [Cursor Origin](https://cursor.com/origin): от команды Graphite, с синхронизацией с GitHub и подписанными вебхуками PR, ревью и пушей.
- [GitLab next-gen SCM](https://about.gitlab.com/blog/gitlab-next-gen-scm/): переписанный бэкенд GitLab с API для агентов без клонирования.

### Git-хранилище для прогонов

Headless git-репозитории с API на первом месте, создаваемые тысячами: ветки, коммиты и диффы, без PR, ревью и шлюзов. Они заполняют половину слота, с короткоживущими токенами на репозиторий, выпускаемыми на каждый прогон.

**Выбирай его, когда** прогонам нужны дешёвые черновые репозитории или форки на прогон (форк на тикет, рабочее состояние агента), а PR всё равно попадает на полноценный git-хостинг одного из типов выше.

- [Cloudflare Artifacts](https://www.cloudflare.com/product/artifacts/): git-совместимое хранилище на Workers; форк базовой версии на каждое задание.
- [Pierre code.storage](https://code.storage/docs): white-label git API с эфемерными ветками.

## Что исследовать дальше

Проверь каждого кандидата по этим вопросам:

1. **Триггеры**: какие события (открыт PR, пуш, отправлено ревью, добавлена метка, завершена проверка) доходят до оркестратора как вебхуки, и подписаны ли доставки?
2. **Идентичность**: может ли прогон действовать как отдельная бот- или app-идентичность? Это сохраняет атрибуцию прогонов, позволяет прогону автоматического ревью одобрить PR, написанный другой идентичностью, и определяет, запускают ли собственные пуши прогона следующий прогон.
3. **Шлюзы**: доступны ли обязательные проверки, обязательные одобрения и защита веток на плане пользователя и при видимости его репозитория, и можно ли поставить бота в список обхода?
4. **Rate limits**: какой бюджет API делят все прогоны на всех раннерах, в какой единице (установка, токен, пользователь, рабочее пространство), и как он масштабируется?
5. **Заполняемые слоты**: какие из слотов трекера тикетов, оркестратора, раннера и платформы наблюдаемости покрывает тот же продукт?

Ищи ответы в первоисточниках: справочник по REST API и вебхукам, страница rate limits, страница цен и сравнения планов, документация по токенам доступа или приложениям, changelog или release notes.

Быстрее всего устаревает: статус беты и превью (целиком типы «изначально для агентов» и git-хранилище), числа rate limits, какой план открывает шлюзы, и доступность после поглощений, закрытий и повторных открытий. Например, на 2026-10 AWS CodeCommit снова открылся для новых клиентов, а Bitbucket Data Center продавался только как гибридная лицензия вместе с Cloud.

## Устойчивые подводные камни

Прежде чем схема на что-то из этого опирается, проверь, что оно всё ещё верно.

- **`GITHUB_TOKEN` в GitHub обрывает цепочки.** События, вызванные встроенным токеном Actions, не запускают новых workflow-прогонов (кроме `workflow_dispatch` и `repository_dispatch`), поэтому прогон, пушащий с ним, молча останавливает следующий прогон. С первого дня давай прогонам идентичность GitHub App.
- **Шлюзы часто спрятаны за платным планом.** На 2026-10 rulesets GitHub в приватных репозиториях требуют Pro, Team или Enterprise, правила одобрения GitLab требуют Premium, а принудительные merge checks в Bitbucket требуют Premium.
- **Rate limits считаются на идентичность, и тип бота их меняет.** На 2026-10 установка GitHub App получает 5 000 запросов в час против 1 000 у `GITHUB_TOKEN`; пользовательские токены Bitbucket остаются на базовом лимите, а токены доступа масштабируются; Azure DevOps поднимает бюджет бота вместе с его уровнем доступа.
- **Трекеры в составе пакета означают два потока событий.** Оркестратор сам объединяет события git-хостинга и трекера тикетов.
