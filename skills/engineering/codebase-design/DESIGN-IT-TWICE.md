# Спроектируй дважды

Когда пользователь хочет исследовать альтернативные интерфейсы для выбранного кандидата на углубление, используй этот паттерн с параллельными субагентами. Основан на «Design It Twice» (Остерхаут): твоя первая идея вряд ли окажется лучшей.

Использует словарь из [SKILL.md](SKILL.md): **модуль**, **интерфейс**, **шов**, **адаптер**, **рычаг**.

## Процесс

### 1. Очерти пространство задачи

Прежде чем запускать субагентов, напиши для пользователя объяснение пространства задачи для выбранного кандидата:

- Ограничения, которым должен удовлетворять любой новый интерфейс
- Зависимости, на которые он будет опираться, и к какой категории они относятся (смотри [DEEPENING.md](DEEPENING.md))
- Грубый иллюстративный набросок кода, чтобы конкретизировать ограничения: не предложение, а лишь способ сделать ограничения конкретными

Покажи это пользователю и сразу переходи к шагу 2. Пользователь читает и думает, пока субагенты работают параллельно.

### 2. Запусти субагентов

Запусти параллельно 3+ субагентов, каждого с чистым контекстным окном. Каждый должен выдать **радикально другой** интерфейс для углублённого модуля.

Дай каждому субагенту отдельный технический бриф (пути к файлам, детали связанности, категория зависимостей из [DEEPENING.md](DEEPENING.md), что стоит за швом). Бриф не зависит от объяснения пространства задачи для пользователя из шага 1. Дай каждому агенту своё проектное ограничение:

- Агент 1: «Минимизируй интерфейс: не больше 1–3 точек входа. Максимизируй рычаг на точку входа.»
- Агент 2: «Максимизируй гибкость: поддержи много сценариев использования и расширение.»
- Агент 3: «Оптимизируй под самого частого вызывающего: сделай случай по умолчанию тривиальным.»
- Агент 4 (если применимо): «Спроектируй вокруг портов и адаптеров для зависимостей через шов.»

Включи в бриф и словарь [SKILL.md](SKILL.md), и словарь GLOSSARY.md, чтобы каждый субагент называл вещи согласованно с архитектурным языком и языком предметной области проекта.

Каждый субагент выдаёт:

1. Интерфейс (типы, методы, параметры, плюс инварианты, порядок, режимы ошибок)
2. Пример использования, показывающий, как вызывающие его используют
3. Что реализация прячет за швом
4. Стратегию зависимостей и адаптеры (смотри [DEEPENING.md](DEEPENING.md))
5. Компромиссы: где рычаг большой, а где слабый

### 3. Представь и сравни

Представляй варианты дизайна последовательно, чтобы пользователь мог усвоить каждый, затем сравни их в прозе. Сопоставь по **глубине** (рычаг на интерфейсе), **локальности** (где сосредоточены изменения) и **размещению шва**.

После сравнения дай собственную рекомендацию: какой вариант дизайна ты считаешь самым сильным и почему. Если элементы разных вариантов дизайна хорошо сочетаются, предложи гибрид. Имей мнение: пользователю нужна уверенная оценка, а не меню.
