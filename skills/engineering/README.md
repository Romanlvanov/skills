# Engineering

Скиллы, которыми я каждый день пользуюсь в работе с кодом.

## Вызываются пользователем

Доступны только когда ты набираешь их вручную (Claude Code: `disable-model-invocation: true`; Codex: `policy.allow_implicit_invocation: false` в `agents/openai.yaml`).

- **[ask-matt](./ask-matt/SKILL.md)**: спроси, какой скилл или сценарий подходит к твоей ситуации. Маршрутизатор по скиллам этого репозитория, вызываемым пользователем.
- **[grill-with-docs](./grill-with-docs/SKILL.md)**: сессия допроса (grilling), которая заодно строит модель предметной области проекта: уточняет терминологию и по ходу обновляет `GLOSSARY.md` и ADR.
- **[triage](./triage/SKILL.md)**: проводит задачи через конечный автомат ролей триажа.
- **[improve-codebase-architecture](./improve-codebase-architecture/SKILL.md)**: сканирует кодовую базу в поисках возможностей для углубления, показывает их в виде наглядного HTML-отчёта, а затем устраивает допрос по выбранной.
- **[setup-matt-pocock-skills](./setup-matt-pocock-skills/SKILL.md)**: настраивает репозиторий для инженерных скиллов (трекер задач, метки триажа, структура документов предметной области). Запусти один раз на каждый репозиторий.
- **[to-spec](./to-spec/SKILL.md)**: превращает текущий разговор в спецификацию и публикует её в трекер задач.
- **[to-tickets](./to-tickets/SKILL.md)**: разбивает любой план, спецификацию или разговор на набор тикетов-трассирующих пуль, каждый с указанием блокирующих связей: текстом в локальном файле или нативными блокирующими ссылками в настоящем трекере.
- **[implement](./implement/SKILL.md)**: реализует работу, описанную спецификацией или набором тикетов, применяя `/tdd` на заранее согласованных швах и завершая `/code-review` перед коммитом.
- **[implement-spec](./implement-spec/SKILL.md)**: реализует целую спецификацию на одной интеграционной ветке. Обрабатывает тикеты как граф задач, запуская субагентов-исполнителей по всему готовому фронту для максимального параллелизма, и завершает `/code-review`.
- **[wayfinder](./wayfinder/SKILL.md)**: планирует огромный объём работы (больше, чем вмещает одна сессия агента) в виде общей карты тикетов-решений в трекере задач; тикеты разрешаются по одному, пока путь к пункту назначения не станет ясен.
- **[retro](./retro/SKILL.md)**: после сессии предлагает улучшения окружения агента (навигация, автоматические проверки, стандарты кода, управляющие файлы, инструменты), начиная с самых серьёзных.

## Вызываются моделью

Доступны модели и пользователю (подробные фразы-триггеры, чтобы модель могла к ним потянуться).

- **[prototype](./prototype/SKILL.md)**: строит одноразовый прототип, чтобы ответить на вопрос дизайна: один HTML-файл, которым можно поделиться (для состояния и логики), или несколько переключаемых вариантов UI.

- **[diagnosing-bugs](./diagnosing-bugs/SKILL.md)**: дисциплинированный цикл диагностики трудных багов и регрессий производительности: построй цикл обратной связи, который становится красным на этом баге → минимизируй → выдвинь гипотезу → добавь инструментирование → исправь → напиши регрессионный тест.
- **[research](./research/SKILL.md)**: исследует вопрос по первоисточникам с высоким доверием и фиксирует выводы в Markdown-файле со ссылками в репозитории; работает как фоновый агент.
- **[tdd](./tdd/SKILL.md)**: разработка через тестирование с циклом red-green-refactor. Строит фичи или исправляет баги по одному вертикальному срезу за раз.
- **[domain-modeling](./domain-modeling/SKILL.md)**: активно строит и уточняет модель предметной области проекта: оспаривает термины, проверяет их на сценариях и по ходу обновляет `GLOSSARY.md` и ADR.
- **[codebase-design](./codebase-design/SKILL.md)**: общая дисциплина и словарь для проектирования глубоких модулей: маленькие интерфейсы, чистые швы, тестируемость через интерфейс.
- **[code-review](./code-review/SKILL.md)**: ревью диффа от фиксированной точки по двум осям: **Standards** (соответствует ли код стандартам репозитория плюс базовому набору запахов по Фаулеру?) и **Spec** (точно ли он реализует исходную задачу или спецификацию?); оси проверяются параллельными субагентами.
- **[pr](./pr/SKILL.md)**: какой вид должно иметь описание pull request: краткое изложение в виде минимальной наглядной схемы, которая проясняет изменение, доказательства работы до и после, и оценка опасности мержа (дверь в одну или в обе стороны, плюс радиус поражения).
- **[wizard](./wizard/SKILL.md)**: генерирует интерактивный bash-мастер, который проводит человека через шаги, выполнимые только им: развёртывание инфраструктуры, настройка учётных данных или секретов CI, проход по незнакомой сторонней панели управления, разовая миграция или переключение.
