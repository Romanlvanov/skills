# Триаж

Проводи задачи (issues) в трекере задач проекта через небольшой конечный автомат ролей триажа.

Если этот репозиторий считает внешние pull request источником запросов (см. конфигурацию трекера задач), триаж охватывает и их: **PR это задача с приложенным кодом**, с теми же ролями, теми же состояниями и тем же автоматом, плюс несколько отличий, помеченных ниже «для PR». Голый `#42` определяй как задачу или PR по конфигурации трекера.

Каждый комментарий или задача, которые ты публикуешь в трекер задач во время триажа, **обязаны** начинаться с этой оговорки:

```
> *This was generated by AI during triage.*
```

## Справочные документы

- [AGENT-BRIEF.md](AGENT-BRIEF.md): как писать долговечные брифы для агента
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md): как устроена база знаний `.out-of-scope/`

## Роли

Две роли **категории**:

- `bug`: что-то сломано
- `enhancement`: новая фича или улучшение

Пять ролей **состояния**:

- `needs-triage`: мейнтейнеру нужно оценить
- `needs-info`: ждём от автора задачи дополнительную информацию
- `ready-for-agent`: полностью описана, готова для AFK-агента (агент работает сам)
- `ready-for-human`: нужна реализация человеком
- `wontfix`: делаться не будет

Для PR те же состояния читаются применительно к приложенному коду: `ready-for-agent` значит, что бриф приложен и агенту следует сделать следующий шаг по диффу; `ready-for-human` значит, что PR готов к слиянию человеком.

У каждой прошедшей триаж задачи должна быть ровно одна роль категории и одна роль состояния. Если роли состояния конфликтуют, сообщи об этом и спроси мейнтейнера, прежде чем делать что-либо ещё.

Это канонические имена ролей. Реальные строки меток в трекере задач могут отличаться. Соответствие тебе должны были предоставить. Если нет, скажи пользователю запустить `/setup-matt-pocock-skills`.

Переходы состояний: задача без меток обычно сначала попадает в `needs-triage`; оттуда она переходит в `needs-info`, `ready-for-agent`, `ready-for-human` или `wontfix`. `needs-info` возвращается в `needs-triage`, как только автор задачи ответит. Мейнтейнер может переопределить состояние в любой момент; о переходах, которые выглядят необычно, сообщай и спрашивай, прежде чем продолжать.

## Вызов

Мейнтейнер вызывает `/triage` и описывает, чего хочет, обычным языком. Пойми запрос и действуй. Примеры:

- «Покажи всё, что требует моего внимания»
- «Давай посмотрим #42» (задача или PR)
- «Переведи #42 в ready-for-agent»
- «Что готово, чтобы агенты это взяли?»

## Покажи, что требует внимания

Запроси трекер задач и покажи три группы, от самых старых:

1. **Без меток**: триаж ещё не проводился.
2. **`needs-triage`**: оценка в процессе.
3. **`needs-info` с активностью автора задачи после последних заметок триажа**: нужна повторная оценка.

Когда PR входят в охват, включай внешние PR в эти группы и помечай каждую строку `[PR]` или `[issue]`. Поиск выдаёт только *внешние* PR (кто считается внешним, определяет конфигурация трекера), поэтому текущий PR участника команды не является работой для триажа. Этот фильтр действует только при поиске; явно названный PR всегда проходит триаж, кто бы его ни написал.

Покажи количества и однострочное описание каждого элемента. Дай мейнтейнеру выбрать.

## Триаж конкретной задачи или PR

1. **Собери контекст.** Прочитай задачу или PR целиком (тело, комментарии, метки, автора, даты; для PR также дифф). Разбери прежние заметки триажа, чтобы не переспрашивать решённые вопросы. Исследуй кодовую базу, используя глоссарий предметной области проекта и учитывая ADR в этой области. Выполни две проверки по кодовой базе: (a) **избыточность**: поищи существующую реализацию запрошенного поведения по понятию предметной области (а не только по формулировке запроса) и сообщи, где искал. Если нашёл, это `wontfix` с причиной «уже реализовано» (шаг 5). (b) **прежний отказ**: прочитай `.out-of-scope/*.md` и покажи всё, что похоже на этот запрос.

2. **Порекомендуй.** Скажи мейнтейнеру, какие категорию и состояние ты рекомендуешь и почему, плюс краткую сводку по кодовой базе, относящуюся к запросу (включая то, реализовано ли это уже). Жди указаний.

3. **Проверь утверждение.** До любого допроса (grilling) проверь, что утверждение подтверждается. Для бага воспроизведи его по шагам автора задачи. Для PR убедись, что дифф делает то, что заявлено: переключись на него, запусти соответствующие тесты или команды. Сообщи результат: подтверждено (с путём выполнения в коде), не воспроизвелось или недостаточно деталей (сильный сигнал для `needs-info`). Подтверждённая проверка делает бриф для агента гораздо сильнее.

4. **Допроси (если нужно).** Если запрос нужно доработать, вызови инструмент Skill дважды, с "grilling" и "domain-modeling", и допрашивай, пока запрос не обретёт форму, по одному раунду вопросов за раз, уточняя термины предметной области и обновляя `GLOSSARY.md`/ADR по ходу, как только принимаются решения.

5. **Примени результат:**
   - `ready-for-agent`: опубликуй комментарий с брифом для агента ([AGENT-BRIEF.md](AGENT-BRIEF.md)).
   - `ready-for-human`: та же структура, что у брифа для агента, но укажи, почему это нельзя делегировать (решения на усмотрение человека, внешний доступ, проектные решения, ручное тестирование).
   - `needs-info`: опубликуй заметки триажа (шаблон ниже).
   - Для `wontfix` закрой задачу, а комментарий зависит от того, *почему*:
     - **Уже реализовано**: изменение уже есть в кодовой базе. Укажи, где оно находится; **не** пиши в `.out-of-scope/` (эта база знаний для *отклонённых* запросов, а не сделанных).
     - **Отклонено (баг)**: дай вежливое объяснение, затем закрой.
     - **Отклонено (улучшение)**: запиши в `.out-of-scope/`, сошлись на это из комментария, затем закрой ([OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)).
   - `needs-triage`: примени роль. Комментарий по желанию, если есть частичный прогресс.

## Быстрое переопределение состояния

Если мейнтейнер говорит «переведи #42 в ready-for-agent», доверься ему и примени роль напрямую. Подтверди, что собираешься сделать (смена ролей, комментарий, закрытие), затем действуй. Допрос пропусти. Если переводишь в `ready-for-agent` без сессии допроса, спроси, хочет ли он написать бриф для агента.

## Шаблон needs-info

```markdown
## Triage Notes

**What we've established so far:**

- point 1
- point 2

**What we still need from you (@reporter):**

- question 1
- question 2
```

Заноси всё, что решено во время допроса, под «established so far», чтобы работа не потерялась. Вопросы должны быть конкретными и выполнимыми, а не «пожалуйста, предоставьте больше информации».

## Возобновление прошлой сессии

Если на задаче или PR уже есть заметки триажа, прочитай их, проверь, ответил ли автор задачи на открытые вопросы, и покажи обновлённую картину, прежде чем продолжать. Не переспрашивай решённые вопросы.
