# Механика скиллов

Ветвь [`writing-for-agents`](SKILL.md), специфичная для скиллов: что меняется, когда документ является скиллом (frontmatter, выбор способа вызова и скиллы-маршрутизаторы). Всё остальное о том, как его писать, лежит в универсальной справке в `SKILL.md`.

## Вызов

Два варианта, которые обменивают одну из двух нагрузок на другую:

- Скилл, **вызываемый моделью**, сохраняет `description`, так что агент может запускать его самостоятельно, и другие скиллы могут до него дойти. Ты по-прежнему можешь набрать его имя: вызов моделью всегда _включает_ доступ пользователя; описание только добавляет обнаружение агентом и никогда не отнимает доступ у человека. Описание служит контекстным указателем скилла верхнего уровня, который обязан всегда оставаться загруженным: постоянная контекстная нагрузка в обмен на обнаруживаемость. Скилл, вызываемый моделью, содержимое которого целиком справка, также служит домом для общей справки: другой скилл может его вызвать, так что справка, нужная нескольким скиллам, живёт в одном месте. Механика: не указывай `disable-model-invocation` и напиши описание для модели с ветвями-триггерами (правила написания указателей из `SKILL.md` применяются полностью).
- Скилл, **вызываемый пользователем**, убирает описание из досягаемости агента: вызвать его может только человек, набрав имя, и ни один другой скилл не может. Нулевая контекстная нагрузка, но тратится когнитивная: индексом служишь ты, и тебе надо помнить, что он существует. Механика: поставь `disable-model-invocation: true`; `description` становится описанием для человека: краткое описание в одну строку, без списков триггеров.

Выбирай вызов моделью, только когда агент должен сам дойти до скилла или до него должен дойти другой скилл. Если он всегда запускается только вручную, сделай его вызываемым пользователем и не плати контекстную нагрузку.

Общая справка, нужная двум скиллам, вызываемым пользователем, не может жить ни в одном из них: без описаний ни один не может запустить другой. Вынеси её в обычный файл вне системы скиллов: внешнюю справку, на которую может указывать любой скилл.

## Деление по способу вызова

Разрез деления по способу вызова (разрез по последовательности описан в `SKILL.md`): выделяй скилл, вызываемый моделью, когда у тебя есть отдельное опорное слово, которое должно запускать его само по себе (слово-триггер, которое ты действительно используешь в своих промптах), или когда до него должен дойти другой скилл. Ты платишь контекстную нагрузку за новое постоянно загруженное описание, так что независимый доступ должен того стоить.

## Скиллы-маршрутизаторы

Когда скиллов, вызываемых пользователем, становится больше, чем ты можешь запомнить, эту накопившуюся когнитивную нагрузку лечит **скилл-маршрутизатор**: один скилл, вызываемый пользователем, который называет остальные и когда к какому обращаться, так что человеку нужно помнить один скилл вместо многих. Он может только подсказывать, но никогда не запускает их: у скиллов, вызываемых пользователем, нет описания, поэтому до них не может дойти никто, кроме человека.
